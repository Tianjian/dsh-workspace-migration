# 05 · 发布前的脱敏清单

把迁移过程开源时，**文件内容不是唯一的泄露面**：路径、名称、日志片段、提交历史都会带出信息。

## 必须替换

| 类别 | 例子 | 处理 |
| --- | --- | --- |
| 用户目录 | `C:\Users\<真实用户名>\...`、`/home/<name>/...` | 改成 `$HOME` / `C:\Users\me` / `<you>` |
| 工作区名称 | 真实项目名、客户名、公司名 | 改成 `workspace-01`、`alpha`、`beta` |
| 会话标题 | 任务标题常含业务信息 | 同上，或不写具体标题 |
| 模型/账号 | 内部模型名、组织 id、邮箱 | 用 `<model>` / `<provider>` 占位 |
| 凭据 | API Key、OAuth token、cookie | **绝不出现**；日志里也要先过滤 |
| 设备信息 | device-id、机器名、SID | 不写 |
| 规模数字 | 精确的客户数据量 | 可保留量级，或所有数字统一用示例值 |

## 检查方法

```powershell
# 在仓库根目录跑，命中即需处理
git grep -n -I -E 'C:\\Users\\[A-Za-z0-9._-]+' -- .        # 真实用户目录
git grep -n -I -E '(ghp_|github_pat_|sk-|AKIA)[A-Za-z0-9]'  # 密钥前缀
git grep -n -I -E '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}'  # 邮箱
git grep -n -I -E '<你的项目名1>|<你的公司名>'               # 业务词
```

提交前再扫一遍 `git log -p` 里的历史（如果曾经提交过敏感内容，改文件没用，要重写历史）。

## 脚本层面的脱敏

- 所有路径通过参数传入（`--db`、`--source-root`、`--dest-root`、`--registry`），**不写死任何默认绝对路径**；
- 日志只打印相对路径或工作区序号；
- 不打印凭据（GitHub 凭据从系统凭据管理器读取时，只输出 `len` 与类型）。

## 会话内容里的脱敏

本仓库生成"内容与产出物"清单时，**只输出文件类型、相对路径、体积**，不输出文件正文，也不输出会话标题里的业务描述。如果你要发布真实清单，请先人工过一遍文件名（文件名本身经常包含客户名）。

## 许可与署名

LICENSE 里的版权人用个人/组织名即可，不必写邮箱；Git 提交者信息会随 commit 公开，介意的话用 noreply 邮箱。
